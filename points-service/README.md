# Points-service

## Обязанности

- Начисление/списание очков по бизнес-правилам 
- Хранение баланса пользователей 
- Предоставление API для получения информации о баллах

## Особенности

1. Event-Driven Architecture: Сервис реагирует на события из Kafka
2. Идемпотентность: Проверка дубликатов через eventId
3. Масштабируемость:
   - Конкурентные consumers 
   - Отдельные БД для чтения/записи (можно добавить позже)
4. Отказоустойчивость:
   - Dead Letter Queue для проблемных событий
   - Retry механизмы
   - - Оптимистичные блокировки через @Version
5. Гибкие правила: JSON правила + формулы вычисления
6. Атомарность операций: @Transactional гарантирует согласованность
7. API для чтения: Разделение команд и запросов
8. Аудит: Полная история транзакций
9. Groovy для формул расчета очков: 
   - Гибкость для исследований: Сложные формулы без перекомпиляции кода
   - Динамическое изменение правил: Можно менять формулы "на лету" через админку

## Полная структура очков и расчетов

### Иерархия очков:

PointsSystem
├── PointsAccount (баланс пользователя)
│   ├── totalPoints (всего заработано за всё время)
│   ├── availablePoints (можно тратить сейчас)
│   ├── frozenPoints (заблокировано)
│   └── level (уровень, производная от totalPoints)
│
├── PointsTransaction (атомарная операция)
│   ├── pointsDelta (+/- значение)
│   ├── type (EARN/SPEND/TRANSFER/CORRECTION)
│   ├── status (PENDING/COMPLETED/FAILED/ROLLED_BACK)
│   ├── ruleId (по какому правилу)
│   └── eventId (исходное событие)
│
└── RuleEntity (правило начисления)
├── pointsValue (фиксированное значение)
├── formula (динамическая формула)
├── conditions (условия применения)
├── limits (лимиты)
└── priority (приоритет)

### Процесс расчета:

```
1. Событие от LMS → Kafka
   {
     "eventId": "uuid",
     "userId": "student123",
     "eventType": "TASK_COMPLETED",
     "payload": {
       "courseId": "java101",
       "taskId": "task1",
       "score": 85,
       "difficulty": "MEDIUM"
     }
   }

2. PointsService получает событие
   ↓

3. RuleEngine находит применимые правила
   - Фильтр по eventType
   - Проверка isActiveAt(now)
   - Проверка условий из payload
   - Сортировка по priority
   ↓

4. Для каждого правила PointsCalculator вычисляет очки
   - Если есть formula: вычисляет Groovy
   - Иначе: берет pointsValue
   - Проверяет лимиты (maxDaily, maxTotal)
   ↓

5. TransactionService создает транзакцию
   - Проверка дубликата по eventId
   - Создание PointsTransaction
   - Обновление PointsAccount
   - Отправка в Kafka (points.changed)
   ↓

6. Обновление уровня
   - level = floor(sqrt(totalPoints / 1000)) + 1
```

- Балансовая система:
  - Разделение очков на total/available/frozen
  - Уровневая система (простая: каждые 1000 очков = новый уровень)
- Транзакционная модель:
  - Атомарные операции начисления/списания
  - Полный аудит всех операций
  - Поддержка идемпотентности через eventId
- Система правил
  1. Rule Engine - движок для применения бизнес-правил
  2. Гибкие правила:
     - Фиксированные начисления 
     - Динамические формулы (Groovy)
     - Условия применения 
     - Лимиты (дневные/общие)
     - Приоритетность
  3. Кэширование правил для производительности
- Интеграционные возможности:
  - Адаптер для разных LMS через Kafka события
  - REST API для запросов баланса, истории транзакций
  - Подготовка для других сервисов (achievements, leaderboard)
